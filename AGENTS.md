# AGENTS.md

ConversiaCore is an embeddable AI tutor widget (the `<conversia-app>` custom element) plus a standalone SPA, backed by a Cloudflare Worker AI proxy (`worker/`) and a Firebase Firestore knowledge base. It is vanilla TypeScript + Vite — no UI framework. Feature specs (spec, plan, tasks, contracts) live in `specs/ai-homework-chatbot/`.

## Toolchain

- Vite 7 + TypeScript 5.7 (strict, `noUnusedLocals`/`noUnusedParameters`), Vitest + jsdom.
- CI (`.github/workflows/deploy.yml`) uses pnpm 10 + Node 20 (`pnpm install --frozen-lockfile`) — prefer pnpm. Both `pnpm-lock.yaml` and a stale root `package-lock.json` exist; don't regenerate the other manager's lockfile.
- `worker/` is a separate npm package (own `package-lock.json`, wrangler 4).
- No linter/formatter is configured (no eslint/prettier/biome anywhere in the repo).

## Commands

- `pnpm install`
- `pnpm run dev` — Vite dev server, http://localhost:5173 (`/admin` for the admin UI)
- `pnpm run build` — `tsc -b && vite build && vite build --config vite.config.widget.ts`. Order matters: the widget build runs after the SPA build so it doesn't wipe `dist/` (its config sets `emptyOutDir: false`).
- `pnpm run build:app` / `pnpm run build:widget` — individual halves; `pnpm run preview` serves `dist/`
- `pnpm test` — `vitest run`, include glob `tests/unit/**/*.test.ts`
- Worker: `cd worker && npm install && npm run dev` (wrangler dev), `npm run deploy` (see `worker/package.json`)
- Type-check only: `npx tsc -b`

## Setup / environment

- `.env.example` lists provider and `VITE_FIREBASE_*` keys, but `VITE_WORKER_BASE_URL` is NOT in it (it currently lives in `.env.local`). The client never calls AI providers directly — `isXConfigured()` in `src/config.ts` only checks `WORKER_BASE_URL`, and all AI calls go through the worker proxy. Never call provider APIs from client code.
- Worker-side keys (`GEMINI_API_KEY`, `GROQ_API_KEY`, `OPENROUTER_API_KEY`, `DEEPSEEK_API_KEY`, `HUGGING_FACE_API_KEY`) are wrangler secrets: `wrangler secret put <NAME>` run from `worker/`.
- The worker's CORS allowlist is hardcoded in `worker/src/index.ts` (`ALLOWED_ORIGINS_EXACT`, plus any `http://localhost:*`). A new deploy origin must be added there or requests fail.

## Conventions (as observed in the code)

- Layout: `src/services/` (AI providers, RAG, guardrails, worker client), `src/ui/{admin,chat,shared}/` (UI modules, no framework), `src/db/` (Firestore + IndexedDB via `idb`), `src/i18n/`, `src/models/`, `src/utils/`.
- Adding an AI provider: implement `AiProvider` from `src/services/ai-provider.ts`, register it in `AI_PROVIDERS` and `PROVIDER_DISPLAY` in `src/services/ai-provider-registry.ts`. Raise failures as `AiProviderError(providerId, kind, message)` — don't throw bare strings.
- Shared limits/constants belong in `src/models/constants.ts` (subjects, grade levels 1–20) or `src/config.ts` (model ids, temperature, token caps). Model ids there carry "verified live on <date>" comments — provider model ids churn; re-verify instead of guessing.
- Every user-facing string goes through `src/i18n/translations.ts` (locales `en`/`fr`/`es`).
- Source files use CRLF line endings.

## Pitfalls

- `pnpm test` runs `vitest run` against `tests/unit/**/*.test.ts` (jsdom env). First run of the session can be slow (~20s, worker spin-up); subsequent runs ~2s.
- `src/dataconnect-generated/` is Firebase Data Connect output — never hand-edit it.
- `dist/` is gitignored build output, fully regenerated by `pnpm run build`.
- Pushing to `main` auto-deploys to GitHub Pages via `.github/workflows/deploy.yml`; it needs the `GEMINI_API_KEY` / `GROQ_API_KEY` / `OPENROUTER_API_KEY` / `VITE_FIREBASE_*` repository secrets to succeed.
